# 配置表说明（Excel ↔ JSON）

> 游戏运行读的是 `resource/config/*.json`，但**这些 json 是从 `excel/*.xlsx` 导出的**。
> 两边不同步的时候，谁覆盖谁要搞清楚 —— 这个文件就是记这件事的。

---

## 1. 关系与工具

```
GunfireDungeon_Godot/
├─ excel/*.xlsx                 ← 配置的【源头】
├─ excelTool/                    ← 导出工具（C#，用 Aspose.Cells 读 xlsx）
│   └─ core/ExcelGenerator.cs     · 读表格 → 写 json + 写 ExcelConfig_*.cs 的“结构类”
├─ resource/config/*.json       ← 游戏【运行时】真正读的数据
└─ src/config/ExcelConfig_*.cs  ← 只有字段定义/读取逻辑，不含数据
```

导出命令（**默认参数会直接覆盖仓库里的 config，别乱跑**）：

```powershell
# ⚠️ 不加参数 = 输出到 excelTool/config 和 excelTool/src（相对当前目录），不是仓库
dotnet run --project GunfireDungeon_Godot/excelTool/ExcelTool.csproj

# 安全用法：显式指定输出到临时目录（注意路径末尾要带反斜杠）
dotnet run --project GunfireDungeon_Godot/excelTool/ExcelTool.csproj -c Release -- `
  "<...>\GunfireDungeon_Godot\excel" "<临时目录>\json\" "<临时目录>\code\"
```

工具的行为：**先删掉输出目录，再整份重写**。所以「重跑导出」是一次全量覆盖。

### 刀（`weapon0004`）需要一处代码支持

`BulletBase` 的 **Type 3**（`2001 刀伤害`）不是真弹丸，只用来让近战武器「有子弹」、
从而能走到 `Weapon.OnFire()`（`Knife.cs` 在那里才启用挥刀判定框）。
而 `FireManager` 只认 Type 1（实体）/ 2（激光），会报 `暂未支持的子弹类型: 3`。
`BulletPart.Execute()` 里已加一行判断：Type 3 直接返回空弹丸数组，不再往下生成实例。

## 4. 改配置的推荐流程

1. **改 Excel**（`excel/*.xlsx`）——能改 Excel 就别只改 json；
2. 导出到**临时目录**：
   `dotnet run --project ... -- "<excel>" "<tmp>\json\" "<tmp>\code\"`
3. 用 `_music/diff2.py` 对比临时导出与 `resource/config/`，确认差异符合预期；
4. 用 `_music/merge_new_rows2.py` 把新行并进仓库 json（它保留目标文件原有的
   换行符与中文转义风格，只做追加，已有行的字节完全不动）；
5. 用 `_music/check_new_content.py` 自检：prefab / 图标 / 零件 / 子弹 / 音效 /
   AI 属性是否都存在（没法实机跑的时候，这个就是替代品）；
6. `dotnet build` 确认 0 错误。

> ⚠️ 用 openpyxl 改 xlsx 会让文件变小（丢掉一部分样式/列宽等排版信息），
> **数据本身不受影响**（导出结果与改之前一致）。介意排版的话，改完用 Excel 打开另存一次。

## 5. 加一把新武器要动几张表

以 2026-09-24 加的 **AK47** 为例，一条完整的链路是 5 张表 + 2 个资源文件：

```
ActivityBase.json   weapon0047          ← 名字/品质/价格/说明/Prefab/Icon, Type=5
                                        （NotInRandomPool=false 就自动进随机武器池）
WeaponBase.json     0047                ← 弹夹/射速/散射/换弹/音效
  ├─ __Activity → ActivityBase.weapon0047   （把武器属性接到 Activity 上）
  ├─ PartPack.Fire[0] → PartBase.0013       （开火零件）
  ├─ __Shell → ActivityBase.shell0001
  └─ __BeginReloadSound / __ReloadFinishSound → Sound.json
WeaponBase.json     0047_ai             ← 敌人拿这把枪时的数值（Id 固定为「主Id + _ai」，
  └─ __AiAttackAttr → AiAttackAttr.0001      Weapon.cs 里用 `Id + "_ai"` 查表）
PartBase.json       0013                ← ClassType="Bullet", Param.Bullet → BulletBase.0013
BulletBase.json     0013                ← 真正决定伤害/弹速/射程/击退/特效
```

外加三个文件：

| 文件 | 作用 |
|---|---|
| `prefab/weapon/Weapon0047.tscn` | 场景。照抄 `Weapon0001.tscn`，改 uid、改 SpriteFrames 引用，按新贴图调 `FirePoint` / `ShellPoint` / `Collision` |
| `resource/spriteFrames/weapon/Weapon0047.tres` | 单帧 SpriteFrames，指向贴图 |
| `resource/sprite/weapon/weapon0047/AK47.png` | 贴图，**UI 图标和手持图是同一张**（原项目 14 把武器都是这样）|

**不需要改任何 C#** —— `PreinstallMarkManager.Init()` 扫 `ActivityBase_List`，
`Weapon.InitWeaponAttribute()` 扫 `WeaponBase_List`，都是按表自动注册的。

### 容易踩的坑

| 坑 | 说明 |
|---|---|
| **`_ai` 行不能漏** | `Weapon.cs` 里是 `WeaponBase_Map.TryGetValue(attr.Id + "_ai")`，缺了会 fallback 到玩家数值（小怪拿这把枪就会按玩家射速开火）|
| **射速怎么算** | `Weapon.cs` 里 `_fireInterval = 60 / CurrFiringSpeed`，即 **`StartFiringSpeed / 60` = 每秒发数**。步枪 480 → 8 发/秒，AK47 420 → 7 发/秒 |
| **备用弹药是算出来的** | `AmmoCapacity × Weapon.ReserveMagazineCount`（常量 = 6）。30 发弹夹 → 备用 180 |
| **`Prefab` 是 `"bullet0001"` 不是路径** | `BulletBase.Prefab` 存的是短名，多条 BulletBase 可以共用一个弹丸 prefab（AK47 复用步枪弹丸，只换数值）|
| **敌人子弹伤害会乘 0.2** | `FireManager.CreateSolidBulletData` 里 `role is Enemy` 时 `BaseDamage × 0.2`，所以 `BulletBase` 写 18，小怪打出来只有 4 点 |

## 6. 加一只新敌人要动几张表

以 2026-09-24 加的**精英怪「不死刽子手」`executioner0001`**
（外加它的召唤物 `spirit0001`）为例：

```
ActivityBase.json   executioner0001   ← 名字/说明/Prefab/Icon, Type=4
                                        NotInRandomPool=false → 进随机敌人池
                                        NotInRandomPool=true  → 只能被代码召唤(幽灵走这条)
RoleBase.json       executioner0001   ← Hp / MoveSpeed / Height / Camp / 各项减伤
  └─ __AiAttr → AiRoleAttr.executioner0001
AiRoleAttr.json     executioner0001   ← AttackInterval / ViewRange / ViewAngleRange / Gold
                                        / BloodColor / __BodyFragment(死亡碎块)
```

外加：

| 文件 | 作用 |
|---|---|
| `prefab/role/enemy/UndeadExecutioner.tscn` | 照抄 `EvilWizard.tscn`（都实例化 `AiTemplate.tscn`），改脚本、改 `HurtCollision` 尺寸、改 `FirePoint` |
| `src/game/activity/role/enemy/ExecutionerEnemy.cs` | 行为（不写 C# 的话就只是一只会走路的普通小怪）|
| `src/game/activity/role/enemy/ExecutionerSpriteFrames.cs` | 从图集切动画 |
| `resource/sprite/role/executioner0001/*.png` | 贴图（**注意授权，见下**）|

### 容易踩的坑

| 坑 | 说明 |
|---|---|
| **`RoleBase.Camp` 必须是 3** | `Enemy.OnInit` 里会再设一次 `Camp = CampEnum.Camp2`，但 RoleBase 里也得写 3，不然出生瞬间的阵营判定会错 |
| **`__AiAttr` 不能空** | `Enemy.OnCreateRoleState` 里 `AiAttr == null` 直接 **throw** —— 缺了游戏起不来 |
| **精灵对齐：`centered` 是 true** | `AnimatedSprite2D` 默认把贴图**居中**画在 `Offset` 处，所以偏移是 **`格子中心 − 锚点`**，**不是 `−锚点`**。写成 `−锚点` 会让角色整体偏到左上半个格子去（`WizardSpriteFrames` 就踩过这个坑，2026-09-24 修）。对齐公式见 `RhinoSpriteFrames` / `DeathSpriteFrames` |
| **`Run` / `ReverseRun` 不能缺** | `AiRole.DoMove()` 是无条件 `AnimatedSprite.Play(AnimatorNames.Run)`，缺了会一直报错。素材没有走路动画时，找个躯干起伏的动画顶上 |
| **近战伤害走的是"空手"那条路** | 不拿武器的敌人由 `Role.HandlerCollision` 用 `BareHandMeleeDamageRange`（固定 2~3 点）。要更强就重写 `Role.BareMeleeDamage` / `BareMeleeRepel` / `BareMeleeRadius` 三个 virtual |
| **近战判定要自己挑时机** | `Role.BeginMeleeHitWindow(duration)` 是给子类用的：打开判定框 + 主动查询 + 清空"本次已命中"。玩家挥刀走的是另一条（`Role_Animation.PlayAnimation_MeleeAttack`）|
| **精英怪别跟小怪抢刷新率** | `RandomPool.GetRandomEnemy()` 原来是均匀抽取 —— 池子里 4 种就各 25%，两只精英怪会占掉一半刷怪量。2026-09-24 改成按 `EnemyWeights` 加权（小怪 10 / 精英 1）|

### 素材授权（新敌人最容易忘的一步）

新敌人的贴图**几乎一定带授权限制**（`executioner0001` 就是"可商用但**禁止再分发**"）。
本项目是公开仓库，所以标准动作是：

1. 在素材目录写 `LICENSE.md`（抄页面授权原文 + 逐条对照 + 抓取日期）；
2. 往 `.gitignore` 加 `*.png` / `*.png.import` 两行；
3. 写一个 `restore_*.ps1` 还原脚本（复制改名即可，不必依赖 Python）；
4. 在游戏内「修改说明」浮层加署名；
5. 更新 `docs/素材授权清单.md`。

详见 `resource/sprite/role/executioner0001/LICENSE.md`。
